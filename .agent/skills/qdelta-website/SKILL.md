# 11. MOTION & INTERACTION SYSTEM

Motion is part of the brand, but it must have a job.

Motion may communicate:

- hierarchy
- state
- direction
- feedback
- continuity
- story
- brand personality

## Recommended Motion Levels

### Level 1 — Essential

- button hover/focus
- navigation state
- menu open/close
- form feedback
- loading/success/error

### Level 2 — Experience

- section reveals
- image transitions
- card movement
- subtle parallax
- controlled page/section transitions

### Level 3 — Signature

- scroll storytelling
- advanced timelines
- 3D scenes
- WebGL interactions
- cinematic hero behavior

Use Level 3 selectively.

## Motion Rules

- Prefer `transform` and `opacity` for many UI animations.
- Avoid long entrance sequences that block reading.
- Do not hijack scrolling.
- Do not animate every word/card/shape.
- Use stagger only when it improves hierarchy.
- Preserve usability at 60fps where practical.
- Respect `prefers-reduced-motion`.
- If removing an animation improves the design, remove it.

## React Bits / External Motion Resources

React Bits or other free motion/component resources may be used **selectively** when they add real value.

Rules:

- adapt components to QDelta's design system
- do not paste unrelated flashy demos into the site
- verify licensing/compatibility before use
- avoid dependency bloat
- keep accessibility and reduced-motion behavior
- prefer a coherent visual language over many disconnected effects

---

# 12. 3D RULES

3D should communicate something, not exist because it looks expensive.

Good uses:

- brand/product storytelling
- product visualization
- premium hero focal object
- spatial/editorial narrative
- selected interactive objects

Avoid:

- random spinning objects
- full-page heavy 3D with no business purpose
- desktop-only experiences with broken mobile fallbacks

For production 3D:

- prefer GLB / glTF
- optimize geometry
- compress textures
- limit materials and draw calls
- lazy load when below the fold
- reduce quality on mobile / low-power devices
- provide a static or simplified fallback

If a 3D element creates a large performance cost and adds little value, remove or redesign it.

---

# 13. MEDIA / VIDEO RULES

If a cinematic video is used:

- keep hero loops short where possible
- remove unused audio from muted loops
- use an optimized poster image
- create desktop and mobile variants when necessary
- do not serve 4K video to every visitor
- do not preload large offscreen videos
- use modern delivery formats with practical fallback

For scroll-controlled storytelling, do not automatically export and preload hundreds of heavy JPG/PNG frames.

Use optimized AVIF/WebP image sequences, video scrubbing or Canvas/WebGL only after testing performance.

The first screen should remain usable before the cinematic media finishes loading.

Build QDelta as a **proper Next.js application** suitable for ongoing development, not a disposable single-file mockup.

# 15. PERFORMANCE STANDARD

Performance is part of premium quality, not a cleanup step.

## Core Web Vitals Targets

Aim for good real-user experience:

- LCP ≤ 2.5 s
- INP ≤ 200 ms
- CLS ≤ 0.1

## Internal Lighthouse Goals

Where practical:

- Performance: 90+
- Accessibility: 95–100
- Best Practices: 95–100
- SEO: 95–100

These are internal quality targets, not guarantees.

## Initial Load Budgets

### DIGITAL / Standard Marketing Experience

Preferred initial load: **≤ 1.5 MB**  
Review carefully above: **2 MB**

### SIGNATURE / Heavier Interactive Experience

Preferred initial load: **≤ 2.5 MB**

If significantly heavier, document why and defer non-critical assets.

### Initial JavaScript Guideline

- standard marketing site: preferably ≤ 250 KB transferred/compressed
- heavier interactive Signature experience: preferably ≤ 350 KB where reasonably achievable

Use code splitting and dynamic imports.

## Images

Prefer:

- SVG for logos/icons where appropriate
- AVIF/WebP for photography/product imagery
- responsive image sizes
- explicit dimensions/aspect ratios
- eager loading for real LCP assets
- lazy loading below the fold

Do not ship huge original client images directly to production.

# 23. ANTIGRAVITY WORKING METHOD

When working in the QDelta repository:

1. **Inspect before editing.** Understand the existing Next.js structure, installed packages, styles and current implementation.
2. **Preserve approved brand content.** Do not rewrite finalized brand identity or service names without explicit instruction.
3. **Plan section-by-section.** Prefer controlled improvements rather than rebuilding the entire project.
4. **Keep changes reviewable.** Make one coherent change at a time.
5. **Use real components.** Avoid giant monolithic page files.
6. **Reuse design tokens and patterns.** Do not invent new spacing/radius/color logic per section.
7. **Install dependencies only when justified.** Prefer existing tools or native CSS/React when sufficient.
8. **Review generated code.** AI output is draft code until tested.
9. **Run quality checks.** Lint, typecheck, build and manually test key interactions.
10. **Test responsive behavior.** Do not stop after desktop looks correct.
11. **Check reduced motion.** Motion should gracefully simplify.
12. **Check performance after visual additions.** Especially Canvas, video, 3D, large images and animation packages.
13. **Never expose secrets.** Keep API keys and credentials in appropriate server-side environment variables.
14. **Do not fake content.** Use honest placeholders.
15. **Keep the website deployable after each major milestone.**
